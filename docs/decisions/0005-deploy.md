# 0005. 배포: 혼합형(일일 미리 계산 + 제한된 실시간), 하루 $0.1

- 상태: 채택 (2026-10-29, 사용자 합의: 혼합형 C, 하루 $0.1, 레포 공개)

## 맥락

- 공개 사이트는 누가 입력할 때마다 Claude 비용이 나간다. 사용자 크레딧 총 $5.
- 설명 1건 비용 **추정** (실측 전): 검색 1회 결과 ≈ 3,500자(라이브 측정), 호출 최대 6회 누적 →
  Sonnet 5.5 약 $0.05~0.15, Haiku 5.5 $0.01 미만.
  → 하루 $0.1로 Sonnet은 1~2건뿐. 정답셋 37건 채점도 Sonnet이면 $2~5.
- **실측 (2026-10-29, ADR 0004)**: Haiku 5.5 건당 평균 **$0.0009**, 최대 $0.0016 (정답셋 35건, 평균 토큰 6,138+551).
  추정($0.01 미만)보다 훨씬 싸다. Sonnet 5.5 실측 건당 평균 $0.0143, 최대 $0.0239 (추정 $0.05~0.15보다 쌈).
  정확도는 Sonnet 81% vs Haiku 78% (+1건) → **Haiku 기본 유지** 확정.

## 결정

- **서비스 기본 모델 Haiku 5.5** (ADR 0004의 "Sonnet 기본"을 예산 때문에 변경). `TREND_MODEL`로 교체 가능.
  정답셋은 Haiku 전체 → 여유가 되면 Sonnet은 일부 사례만.
- 입력 토큰 절약: 검색당 기사 15→10건, 요약문 100자.
- **하루 $0.1 = 일일 배치 $0.04 + 실시간 $0.06** (`BATCH_BUDGET_USD`, `LIVE_BUDGET_USD`).
  설명 시작 전 최악 비용(Haiku $0.01)을 예약, 끝나면 실제 비용으로 정산 (`trend_agent/budget.py`).
  예산이 없으면 **탐지 결과는 그대로**(네이버라 무료) 보여주고 설명만 "오늘 한도 소진".
- 실시간: 키워드당 **가장 최근 급등 1건만** 설명, 같은 급등은 캐시, IP당 하루 5회.
- 일일 배치: GitHub Actions(09:17 KST)가 감시 키워드 38개를 탐지하고 최근 3일 급등만 설명 →
  `data` 브랜치 `daily.json`. 앱은 raw URL로 읽는다 → **main이 안 바뀌니 재배포 없음**.
- 호스팅: Render 무료 (기존 에이전트와 동일, `render.yaml`).

## 한계 / 안전장치

- 실시간 예산 카운터는 메모리에만 있어 Render가 잠들었다 깨면 0부터 다시 센다.
  **최종 상한은 Anthropic 콘솔 사용 한도**와 남은 크레딧 자체.
- 감시 키워드 목록은 고정이라 "오늘의 급등"은 전체 급상승어가 아니다 (네이버에 급상승어 API 없음). UI에 명시.
- 예산 예약값 `WORST_CASE_USD` Haiku $0.01은 실측 최대($0.0016)의 약 6배로 보수적이다.
  실제 비용으로 정산하므로 하루 $0.06 실시간 한도에서 평균 약 60건 설명 가능 (예약 때문에 동시 요청이 몰릴 때만 덜 들어감).
