# 0003. 정답셋 형식과 채점 기준

- 상태: 채택 (2026-10-29)

## 맥락

- 목표 문구 "원인이 알려진 급등 사례 N개 기준 원인 적중률 X%"를 재현 가능하게 측정해야 한다.
- 유행형(두쫀쿠)은 몇 주에 걸쳐 오르므로 28일 기준선이 따라 올라가서 시작부만 탐지된다 (ADR 0002 라이브).
- 검색어트렌드는 구간 최대 = 100이라 **조회 구간이 바뀌면 지수도 바뀐다** → 구간을 고정해야 재현된다.

## 결정

### 사례 수집
- 반자동: 분야별 키워드를 탐지기로 돌려 후보를 뽑고, 급등 기간 기사 제목을 붙여 사람이 O/X 검수.
- 사람이 직접 준 사례는 `source: "user"`로 구분 — 탐지기가 놓친 사례(재현율) 확인용.
- `verified: true`인 사례만 점수에 넣는다.

### 데이터 (`eval/cases.json`, `eval/snapshots/<id>.json`)
- 사례마다 **고정 90일 구간**(앱과 동일 길이, `window_start~window_end`)의 검색어트렌드 응답을 스냅샷으로 저장.
  채점은 스냅샷으로 오프라인 실행 → API 데이터가 바뀌어도 점수가 재현되고 호출 한도를 쓰지 않는다.

### 탐지 적중
- 라벨 사건 기간 `event_start~event_end` **±3일**과 겹치는 급등이 하나라도 있으면 적중.
  (정점 일치를 요구하지 않음 — "왜 떴나"는 시작부가 더 중요하고, 두쫀쿠 같은 유행형도 적중 처리)

### 원인 적중 (3단계 출력 채점용)
- 사례마다 핵심어 그룹 `cause_keywords: [[...], [...]]`.
  **모든 그룹**에서 단어 하나 이상이 설명에 등장하고(공백 무시, 대소문자 무시),
  인용 기사 중 하나 이상의 날짜가 사건 기간 ±3일 안이면 적중.
- LLM 채점은 결과가 흔들려서 기각. 표현 다양성 문제는 그룹 안에 동의어를 넣어 해결.

## 1차 결과 (2026-10-29, 미검수 포함 `--all`)

- 37건: 수집 16 + 사용자 21. **탐지 적중 35/37 (95%)**.
- 수집 사례는 탐지기로 뽑았으므로 적중이 당연 → **공정한 지표는 사용자 사례 19/21 (90%)**.
- 놓친 2건은 모두 **코스피** (상시 고검색 + 평일 주기 키워드):
  - 7000 돌파(05-04~08): 기준 19.5 대비 1.2~1.4배
  - 5000대 폭락(07-28~29): 기준 42 대비 1.9~2.4배, z 1.6~2.4
  → "평소에도 많이 찾는 키워드의 큰 사건"은 3배·z 3.5 기준에 못 미친다. 재조정은 검수 후 판단.
- 제외: 이태원 참사 4주기(10-29, 데이터가 어제까지라 아직 없음), 거제 비빔밥(저검색량 판단 불가 + 관련 기사 없음).
- 비상계엄(2024-12-03)은 최근 재판 기사에 밀려 당시 기사 도달 0건 → 원인 채점에서 제외 후보.
