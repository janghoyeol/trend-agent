# 0004. 원인 설명 에이전트 (Claude tool-use)

- 상태: 채택 (2026-10-29, 사용자 합의) — Claude 라이브 확인, Haiku 5.5·Sonnet 5.5 정답셋 채점 완료 (2026-10-29)

## 맥락

- 뉴스 API는 날짜 필터가 없고, 키워드만으로는 과거 급등 기사에 거의 닿지 않는다.
  `sort=sim` + **원인 맥락어**를 붙여야 닿는다 (ADR 0001).
- 원칙: 출처 없는 숫자 금지, 계산은 코드, 지어내기 방지.

## 결정 (`trend_agent/agent.py`)

1. **도구 1개 `search_news(query)`** — Claude가 맥락어를 바꿔가며 재검색, 코드가
   `sort=sim` 500건을 받아 **급등 기간 −2일 ~ +2일** pubDate로 거른 뒤 최대 15건만 보여준다. 검색 최대 5회
   (넘으면 `is_error` 결과로 "지금까지 본 기사로 답하라").
   - 기사에는 코드가 `a1, a2…` id를 붙인다. 같은 링크는 같은 id.
   - 기간 내 기사가 0건이면 **기간 밖 제목 5개를 힌트로** 준다 (id 없음 = 인용 불가).
     라이브: "최저임금", "깐부치킨"은 키워드만으로 기간 내 0건, "최저임금 결정"/"깐부치킨 젠슨황"은 100건+.
     단서가 없으면 Claude가 맥락어를 지어낼 수밖에 없어서 추가.
2. **최종 출력은 structured output** `{status: found|unknown, cause, citations[id]}`.
   코드가 검증: id가 실제로 보여준 기사인지, 날짜가 기간 안인지, 중복 아닌지. 탈락 id는 `rejected`에 기록.
   - 검색량 숫자는 Claude에게 쓰지 말라고 하고, 사람용 문장(`render`)에서 **탐지 결과 값만** 코드가 넣는다.
3. **근거 없으면 "원인 불명"** — `found`인데 유효 인용이 0개면 코드가 `unknown`으로 바꾼다.
   채점에서는 오답 (`cause_hit`는 `found`일 때만 검사).
4. **모델 기본 Sonnet 5.5**, effort `medium`. 정답셋으로 Haiku 5.5와 비교 (`scripts/eval_cause.py --model`).
   - Sonnet은 서버측 거절 폴백(`fallbacks: "default"`)을 켬. 거절되면 `unknown`.
   - 시스템+도구 프롬프트는 고정 → 자동 프롬프트 캐싱 (`cache_control`).

### 채점

- `scripts/eval_cause.py`: 검수 완료 + `cause_eval` 사례. 탐지가 놓친 사례는 Claude를 부르지 않고 오답 (end-to-end),
  탐지된 것 중 적중률도 함께 출력. 결과는 `eval/results/<model>-<effort>.json`.
- **비상계엄(martial-1203)은 원인 채점 제외** (`cause_eval: false`): 당시 기사 도달 0건이라 측정 불가.
  → 원인 채점 대상 37건.

## 기각한 대안

- 코드가 미리 기사를 모아 한 번에 넣기: 맥락어를 사람이/코드가 알아야 해서 과거 급등에 못 닿음.
- 웹 검색 서버 도구: 출처를 네이버 뉴스 pubDate로 검증하는 원칙과 맞지 않음.
- LLM 채점: 흔들림 (ADR 0003).

## 결과 (2026-10-29, 실제 키로 라이브)

- `python scripts/explain_live.py 태풍` (Haiku 5.5): 급등 10-20~26 → "제30호 태풍 '참피' 북상" + 기간 내 기사 3건 인용,
  검색 2회, 토큰 9,424+593, **$0.0012**. 버그 없음.
- `python scripts/eval_cause.py --model claude-haiku-5-5` / `--model claude-sonnet-5-5` (둘 다 effort medium) → `eval/results/<model>-medium.json`

| 모델 | 원인 적중 (37건, end-to-end) | 탐지된 35건 중 | 총 비용 | 건당 평균 (최대) | 평균 토큰 (입력+출력) |
|---|---|---|---|---|---|
| Haiku 5.5 | **29/37 = 78%** | 29/35 = 83% | $0.031 | **$0.0009** ($0.0016) | 6,138 + 551 |
| Sonnet 5.5 | **30/37 = 81%** | 30/35 = 86% | $0.501 | **$0.0143** ($0.0239) | 5,809 + 271 |

비용은 위 토큰 × 단가(Haiku $0.10/$0.50, Sonnet $2/$10 per 1M; `agent.PRICES`)로 코드가 계산.

**결론: Sonnet은 +1건(+3%p)에 비용 16배 → 서비스 기본은 Haiku 5.5 유지** (ADR 0005 예산과도 맞음).
두 모델이 틀린 사례가 서로 달라(아래) 차이 1건은 우연 범위로 본다.

Haiku 오답 8건 분류:
- 탐지 못함 2 — kospi-7000, kospi-crash-0728 (ADR 0002의 기존 한계)
- 원인 불명 2 — kimyk-0926, aiglass-1013: 기간 내 기사에 닿지 못하자 **지어내지 않고 `unknown`** (설계 의도대로).
  뉴스 API가 과거 기사에 잘 닿지 않는 한계 (ADR 0001)
- 원인은 맞지만 인용 기사가 사건 기간 뒤 2 — kkanbu-1030(11-04 기사), chiikawa-1001(10-09~12 기사).
  탐지된 급등 기간이 사건 기간보다 길어 에이전트 검증(급등 기간 ±2일)은 통과했지만, 채점은 사건 기간 인용을 요구
- 표현 불일치 1 — heat-0804: "폭염특보"라고 써서 정답 키워드 "폭염중대경보" 없음
- 다른 원인 1 — gta6-0828: 정답 "유출·250GB" 대신 "플레이 영상 공개"

Sonnet 오답 7건 분류:
- 탐지 못함 2 — 코스피 (위와 같음)
- 인용 기사가 사건 기간 뒤 2 — kimyk-0926(09-29~10-01 기사), assassins-0929(10-06~07 기사)
- 표현 불일치·결과 누락 2 — aiact-1226: "의결"이라 써서 키워드("통과·가결·제정") 없음 /
  impeach-1214: 당일 오후 기사만 인용해 "표결 진행"까지만 쓰고 "가결"이 없음
- 다른 원인 1 — gta6-0828 (Haiku와 같은 답: 플레이 영상 공개)

Haiku만 맞힌 사례: assassins-0929, impeach-1214, aiact-1226 /
Sonnet만 맞힌 사례: heat-0804(폭염중대경보), aiglass-1013(Haiku는 원인 불명), kkanbu-1030, chiikawa-1001(사건 기간 기사 인용).
Sonnet은 맥락어를 더 많이 바꿔 재검색해서(최대 4회) 기사 도달이 낫고, Haiku는 문장에 결과어("가결", "통과")를 더 잘 남긴다.

채점 규칙(ADR 0003)은 결과를 보고 바꾸지 않았다. 소개 문구: **"원인이 알려진 급등 37건 기준 원인 적중률 78% (Haiku 5.5, 건당 약 $0.001)"**.
